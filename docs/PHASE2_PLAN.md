# 第二階段規劃：批次整理與垃圾桶

狀態：2026-09-09 已依序實作並驗收部署。實際行為、限制與檢查結果見 [第二階段驗收](PHASE2.md)。下列保留原規劃作為需求依據。

## 目標與範圍

讓使用者能選取多個檔案或資料夾，複製、搬移、移至垃圾桶並還原，且能看見每個項目的結果。保留既有登入與共用工作空間模式。

| 順序 | 交付內容 | 使用者操作 |
| --- | --- | --- |
| 2A | 批次複製／搬移、目的地選擇、衝突處理、任務紀錄 | 多選 → 複製到／移動到 → 選目的地 → 確認 |
| 2B | 垃圾桶列表、移入垃圾桶、還原 | 多選 → 移至垃圾桶 → 確認；垃圾桶 → 還原 |
| 2C | 剪下／複製／貼上、快捷鍵與操作細節 | Ctrl／Command+C、X、V；Delete 移至垃圾桶 |
| 驗收 | API、瀏覽器與 Docker 測試、錯誤修正、備份與更新 | 在目前 9005 服務驗證完整流程 |

先完成 2A 並驗收，再進入 2B；快捷鍵最後接上同一套操作 API。

## 操作規則

- 批次支援檔案及資料夾。選取父資料夾及其子項目時，合併為父資料夾一次操作，避免重複處理。
- 禁止操作根目錄、將資料夾複製／搬移到自身或自己的子目錄，以及存取符號連結、junction 與內部保留目錄。
- 搬移到原父目錄回報「無須移動」；複製到原目錄需要選擇「保留兩者」才建立副本。
- 同名提供「略過」與「保留兩者」，可套用到整批；預設略過。第二階段不提供覆寫，也不合併同名資料夾。
- 保留兩者使用 `報告 (1).pdf` 等名稱，發布前再次檢查；Windows 大小寫差異依實際檔案系統處理，不假設大小寫敏感。
- 批次不是整批交易：逐項顯示成功、略過、失敗或取消；不因一項失敗回復已完成的其他項目。
- 複製到暫存目的地，完成後才發布。失敗不留下看似成功的半份檔案／資料夾。
- 取消停止尚未完成的複製及後續項目；已發布的項目保留。搬移或垃圾桶的單項提交期間不可取消，介面需說明。
- 複製期間來源若有明顯變動，該項回報失敗並要求重試。這不是檔案系統快照，不承諾與外部程式同時寫入的一致性。

## 任務與後端整理

- 路由只處理驗證與 HTTP；新增批次操作、命名衝突、垃圾桶服務，共用目前的路徑檢查及寫入鎖。
- SQLite 保存任務 ID、操作人、時間、來源／目的地、衝突策略及逐項狀態。新增表格採版本化遷移，保留 users／sessions。
- 第一版使用單一背景工作佇列、同時執行一個批次任務，避免大量遞迴複製堵住 API 或多個批次互相競爭。
- 長操作不持有整段資料庫交易；前端輪詢任務進度，重新整理可重新取得結果。登出後不可查詢或操作任務。
- 寫入前保存意圖，提交後標記結果；重啟時依紀錄與實際檔案核對，不能直接重播所有未完成任務。無法判定時標記需檢查，不自動刪除來源。
- 同一提交識別碼重送須回傳既有任務，避免雙擊或網路重試重複搬移。
- 繼續限制單一 worker／容器寫入同一根目錄。Windows 掛載相容模式不能只靠存在檢查，所有發布操作必須遵守共用鎖。
- 掛載內若跨越其他檔案系統，搬移先明確拒絕；不默默退化成「複製後刪除」。

建議 API 契約（實作前與現有路由整合確認）：

| API | 用途 |
| --- | --- |
| POST `/api/v1/files/operations` | 提交 copy／move／trash，含項目、目的地、衝突策略與提交識別碼；202 + 任務 ID |
| GET `/api/v1/files/operations` | 查詢目前帳號的任務 |
| GET `/api/v1/files/operations/{id}` | 狀態、項目計數、逐項結果 |
| POST `/api/v1/files/operations/{id}/cancel` | 要求取消，回報實際狀態 |
| GET `/api/v1/trash` | 垃圾桶項目與原路徑 |
| POST `/api/v1/trash/restore` | 按不透明項目 ID 還原，202 + 任務 ID |

## 垃圾桶

- 垃圾桶存放於檔案根目錄內的保留目錄，使用不透明 ID 保存內容，避免同名及跨磁碟搬移。
- 一般列表、搜尋、預覽、下載及上傳 API 一律禁止存取此目錄；只能透過垃圾桶服務操作。
- 記錄原路徑、原名稱、刪除時間、操作人、類型與狀態。延續共用空間：所有已授權帳號均可看到並還原垃圾桶項目，介面清楚標示共用。
- 還原優先回到原路徑；父資料夾不存在時請使用者選目的地。同名使用相同的略過／保留兩者規則。
- 先完成操作紀錄再搬移；重啟時核對紀錄與實體內容，防止檔案已移入但垃圾桶列表漏掉。
- 本階段不自動清空、不提供永久刪除。介面說明垃圾桶仍占用磁碟空間；垃圾桶內容與資料庫必須一併備份。

## 前端互動

- 固定選取工具列加入複製到、移動到、移至垃圾桶，右鍵選單提供相同入口。
- 目的地視窗顯示目錄樹、麵包屑及完整相對路徑；禁止選取的目錄需顯示原因。
- 任務面板顯示整體項目進度及逐項結果；失敗項目可重試，不重跑已完成項目。
- 剪下項目淡化，貼上成功後逐項清除剪下狀態。輸入欄位、文字編輯與預覽中的文字選取不攔截原生剪貼簿快捷鍵。
- 不將完整檔案內容寫入系統剪貼簿；剪下／複製記錄只作用於本應用。手機使用按鈕及選單完成同樣流程。

## 必須通過的驗收

1. 多檔與巢狀資料夾複製後，內容、結構及下載位元組一致；搬移後來源消失且目的地完整。
2. 父子重複選取、中文、特殊名稱、同名、Windows 大小寫、根目錄及自身子目錄操作符合規則。
3. 中途取消、磁碟滿、權限不足、來源消失、同名競態不覆寫既有資料；部分成功結果正確。
4. 任務提交重送不重複執行；瀏覽器重新整理可讀取狀態；容器重啟不盲目重播或遺失垃圾桶項目。
5. 移入垃圾桶、還原、父目錄不存在與還原同名衝突都以測試檔案驗證；保留目錄不可從一般 API 讀寫。
6. 未登入、跨帳號任務查詢及不合法 Origin 被拒絕；共用垃圾桶權限符合前述規則。
7. 桌面與手機完整操作，確認選取工具列不位移、快捷鍵不干擾輸入、既有上傳／下載／登入流程無回歸。
8. 在 Docker Desktop 的 Windows bind mount 實測，再備份資料庫、金鑰與檔案根目錄後更新 9005 服務；發現的缺陷修正後重跑相關測試。

不包含：分享連結、使用者配額、獨立空間、檔案版本、全文搜尋、資料夾上傳、ZIP 打包下載及多副本部署。
