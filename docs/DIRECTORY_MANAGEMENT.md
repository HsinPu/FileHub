# 目錄管理與多目錄授權

## 使用方式

Docker 先掛入父目錄，管理員再到「設定 → 目錄管理」登錄要開放的子目錄，最後在「帳號管理」分配權限。登錄與授權儲存在 SQLite，日後新增父目錄底下的共享資料夾，不需要修改 `.env` 或重啟容器。

例如主機 `/nfs` 掛到容器 `/files/nfs`：

| 主機資料夾 | 管理頁填寫的相對路徑 | 顯示名稱 |
| --- | --- | --- |
| /nfs/reports | nfs/reports | 報表中心 |
| /nfs/departments/it | nfs/departments/it | IT 文件 |

基本 Compose 仍使用 Docker `files` 資料卷，不需要外部目錄。選用 NFS 的掛載方式見 [Docker 說明](DOCKER.md)。管理頁只選擇容器已能存取的目錄，不會替主機掛載 NFS。

## 登錄目錄

1. 管理員開啟「設定 → 目錄管理 → 新增目錄」。
2. 輸入顯示名稱，使用資料夾選擇器或填寫相對路徑，例如 `nfs/reports`。
3. 檢查目錄後儲存；系統再次確認路徑可讀、合法且沒有重疊。
4. 到「帳號管理」選擇多目錄授權，新增該目錄並勾選操作權限。

最多登錄 100 筆。不能登錄總根目錄、符號連結、受保護位置，或重複／父子重疊的目錄；停用的項目也保留路徑。可同時登錄 `nfs/reports` 與 `nfs/departments/it`，不能同時登錄 `nfs` 與 `nfs/reports`。

顯示名稱可修改，識別碼與路徑固定。此版提供啟用／停用，不提供永久刪除或直接修改路徑；目錄登錄操作不會建立、搬移或刪除實體資料。

目錄選擇器一次只讀目前層級，最多檢查 200 個項目；清單截斷時可以直接填寫已知路徑。管理頁另列總根目錄狀態，它不是可授權的登錄項目。

## 帳號與導覽

新建帳號預設「多目錄授權」；舊的單一根目錄帳號維持原設定。登錄新目錄不會自動授權任何一般帳號。

多目錄帳號登入後，在「所有目錄」直接看到授權入口及其顯示名稱。例：只有 IT 文件權限的人直接進入 `nfs/departments/it`，不能瀏覽 `nfs` 或 `nfs/departments`。麵包屑與上一層最多回到「所有目錄」，複製／搬移的目的地選擇也遵循相同範圍。

虛擬根不能上傳、建立資料夾或貼上。已授權但目前離線的入口會保留並標示狀態，不會被當成空資料夾。

多目錄 API path 仍相對於系統檔案根目錄，例如 `nfs/reports/2026/report.pdf`；單目錄 API path 相對於該帳號根目錄。顯示名稱不會改變實體路徑。

每個目錄必須有瀏覽權限；分享需同時具備讀取權限。唯讀、一般作業、完整作業範本可快速設定，分享仍須另行勾選。失效或路徑不符的既有授權會標示，不會自動指向新目錄。

## 停用與恢復

停用前會顯示受影響的多目錄帳號、任務、分享，以及仍可存取此範圍的舊單目錄帳號。停用不會刪除資料或授權記錄。

- 受影響多目錄帳號的既有登入撤銷，重新登入後不再看到停用入口。
- 這些帳號的舊任務與分享全部失效，包括同帳號其他目錄的舊任務／分享；執行中的操作於權限檢查點停止，已完成部分保留。
- 重新啟用前須能讀取目錄。恢復後原授權再次適用，但不會恢復舊登入、舊任務或舊分享。
- 只改顯示名稱不撤銷登入或既有權限。
- 管理員及原有單根目錄帳號仍按原範圍存取；若要統一用登錄目錄控制，請先把相關一般帳號改成多目錄模式。

## 操作授權

| 操作 | 多目錄授權條件 |
| --- | --- |
| 瀏覽 | 目前目錄 browse |
| 預覽、下載、ZIP | 每個來源 read |
| 上傳、建立資料夾 | 目的目錄 upload |
| 重新命名 | 來源目錄 modify |
| 複製 | 來源 read，目的 upload |
| 搬移 | 來源 modify，目的 modify + upload |
| 移至垃圾桶 | 來源 delete |
| 還原 | 本人刪除的項目、原路徑仍在授權範圍，目的 upload |
| 分享 | 來源 read + share；公開下載時再次檢查 |

管理員不受一般帳號目錄授權限制。舊單目錄帳號的搬移條件維持 modify。應用程式授權不會更改 Linux 的 UID/GID、ACL 或掛載權限。未增加群組或逐檔案 ACL。

上傳與批次作業在提交前再次檢查授權；ZIP 下載與已驗證的分享 Cookie 也重新檢查。已送出的內容無法收回。登錄目錄及其祖先受保護，不能透過檔案操作搬移、重新命名或移至垃圾桶，即使登錄已停用。

## NFS 與檔案系統限制

目錄管理顯示可讀、不存在、不是資料夾、無法存取等狀態。「寫入權限檢查」只使用作業系統提示，不寫入測試檔；不能保證實際寫入成功。裝置編號也無法辨識所有 bind mount 情況。

垃圾桶集中於檔案根目錄 `.files-app-trash`。跨檔案系統的垃圾桶與還原操作會拒絕；跨掛載搬移同樣須符合既有檔案系統限制。掛入 NFS 後可瀏覽，不代表所有寫入操作都可用。先用隔離測試資料確認上傳、下載、複製、搬移與垃圾桶行為。

同一路徑底下更換主機來源，系統無法自動辨識。部署者應先停用相關入口、確認新來源與權限，再恢復服務。備份需涵蓋 database/config volumes、垃圾桶與所有外部來源；停機後備份，不要使用 `down -v`。

## 升級與 API

資料庫版本 8 新增目錄登錄表。首次初始化將舊 `FILES_DIRECTORIES` 匯入一次；包含空清單也記錄初始化完成。之後以資料庫為準，修改環境變數不會覆蓋管理頁設定。舊授權保留識別碼與路徑快照；遺失的目錄宣告不會自動補建。

更新前備份資料庫、金鑰與資料；回退須還原對應版本的資料庫，不能只降版映像。詳見 [升級紀錄](MIGRATION.md)。

| API | 用途 |
| --- | --- |
| GET /api/v1/admin/directories | 總根狀態、登錄清單與權限提示 |
| POST /api/v1/admin/directories | 登錄目錄 |
| PATCH /api/v1/admin/directories/{id} | 名稱或啟用狀態；必須帶 revision 防止覆蓋他人修改 |
| GET /api/v1/admin/directories/{id}/impact | 停用影響 |
| GET /api/v1/admin/directory-browser?path=... | 有上限的單層目錄選擇器 |
| GET /api/v1/admin/directory-status?path=... | 檢查選定相對路徑 |
| GET /api/v1/directories | 目前帳號可用的多目錄入口 |

上述 admin API 僅管理員可用。新功能計畫與驗證記錄見 [後台目錄登錄計畫](DIRECTORY_REGISTRY_PLAN.md)。以下是先前版本的歷史紀錄。
