# 第二階段：批次整理與垃圾桶

## 完成功能

依 2A → 2B → 2C 順序實作，保留第一階段 API 與帳號。

- 2A：多選檔案及資料夾，複製到／移動到、目的地目錄樹、同名略過／保留兩者、任務面板、取消、失敗項目重試及紀錄分頁。
- 2B：移至共用垃圾桶、原位置或另選位置還原、同名保護、原目錄不存在提示及垃圾桶紀錄分頁。
- 2C：剪下／複製／貼上、剪下項目淡化、成功搬移後清除相應剪貼簿項目；Ctrl／Command+C、X、V 及 Delete 確認移至垃圾桶。

## 資料與執行規則

- 遷移版本 2 新增任務及版本紀錄表，版本 3 新增垃圾桶表；不重建 users／sessions。
- 每次最多 100 個來源、最多 100 個等待／執行中的任務、同時一個背景批次。遞迴掃描上限 100,000 個節點及 128 層；不是已量測的效能承諾。
- 任務保存來源、目的地及逐項結果；提交 UUID 防止重送。只允許擁有者查詢／取消自己的任務；垃圾桶延續共用空間權限。
- 檔案複製以分塊串流寫入保留暫存，再檢查來源並發布。相同來源與目標、父子重複選取、符號連結及不安全路徑會被合併、略過或拒絕。
- 同名不合併資料夾、不覆寫；保留兩者自動加編號。跨檔案系統搬移／還原拒絕執行。
- 任務進度以頂層項目計算，大型單一資料夾處理時可能長時間顯示執行中；上傳進度仍使用第一階段的位元組進度。
- 刷新頁面可重新查詢任務；頁面剪貼簿不持久化。任務可能部分成功，取消及重試不會回復已完成項目。
- 第二階段不提供永久刪除、自動清空、覆寫、ZIP、分享及獨立空間。

## 中斷與維護

- 重啟後不自動重播未完成任務，一律標記「需檢查」，由使用者核對來源與目的地。已完成任務保留原結果。
- 垃圾桶另有 staging／restoring 紀錄，重啟核對來源、保留內容及已記錄的還原目標；可確定的項目回復為可還原或已還原，其餘顯示需維護者檢查。
- 程序被強制終止可能留下 `.files-app-upload-batch-*` 暫存。一般 API 無法存取；停止服務、核對對應任務與完整來源後，維護者才可清理。不要直接重試標記為需檢查的操作。
- 垃圾桶保留目錄為根目錄下 `.files-app-trash`；一般瀏覽／預覽／下載／上傳 API 禁止存取。維護者不可單獨刪除此目錄或清空 trash_items 表。
- 備份必須包含資料庫、金鑰、整個檔案根目錄（含垃圾桶）。Windows 掛載相容模式仍限單一 worker／容器，不能有其他服務同時寫入同一路徑。
- 外部程式同時改動檔案不是隔離快照場景。已加入排隊及複製前後的來源比對；無法對抗本機惡意競態替換。

## 驗證與修正紀錄

- 2A API 測試後才加入 2B；2A／2B 分別通過瀏覽器完整操作，再實作 2C。
- 修正關閉的 Drawer 仍留在 DOM，造成快捷鍵被誤擋的問題；只檢查可見的對話框。
- 修正目的地目錄樹選取後重建導致展開狀態消失的問題。
- 加入排隊期間來源變更拒絕、Windows 掛載實體路徑比較、失敗任務明確顯示異常進度。
- 加入磁碟滿／權限失敗／傳輸取消的暫存清理測試、原檔保留、任務所有權、中斷不重播及垃圾桶還原衝突測試。
- Docker 隔離測試包含批次複製搬移、垃圾桶、容器重建、任務查詢與還原內容比對。
