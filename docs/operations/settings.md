# 帳號、入口與個人設定

工作空間右上「帳號選單 → 設定」開啟獨立設定頁，提供個人檔案偏好及修改自己的密碼。每頁筆數與預設列表／圖磚／圖庫儲存在帳號資料中（0.40.0 起支援圖磚）；工具列暫時切換不自動保存；修改密碼後需重新登入。設定 URL 為 `/?view=settings&section=personal`，管理員另有 `accounts`／`storage`；可重新整理與使用瀏覽器返回，原檔案入口、路徑、排序與版本分頁留在 query 作返回上下文。

管理頁上方以橫向分類切換個人設定、分享與目前入口的垃圾桶；管理員另有帳號／儲存分類。分類可鍵盤 Tab／Enter，手機只在分類列與寬表格內左右捲動。

表單失敗或重新整理設定資料會保留輸入；切分類、側欄、返回與登出共用未儲存確認，取消即繼續編輯。儲存中會阻擋這些轉換並顯示原因；整頁刷新／離開採瀏覽器標準提醒。按「返回檔案」回原瀏覽位置，跨設定頁不會停止上傳或重建背景工作控制器。

管理員另有「帳號管理」與「儲存與授權」。建立帳號時選角色及初始密碼；停用／恢復、角色變更及重設密碼會影響後續授權，至少保留一位啟用管理員。沒有帳號刪除操作。

## 登記現有儲存目錄

先由主機管理者配置 OS／Compose mount，再於同版 FileHub 環境執行：

```sh
pnpm admin entry-offer external '已掛載團隊資料' /mnt/team
```

Docker 部署可由相同 image 的一次性管理服務執行 Node CLI；沿用[部署操作](deployment.md)的身份與掛載，僅將 command 改成 `node apps/server/dist/cli.js entry-offer external 已掛載團隊資料 /mnt/team`。該服務必須真的掛有 `/mnt/team`，且 API／worker 用相同路徑與必要權限。範例路徑是占位值，請依部署調整。

到「儲存與授權」選候選、輸入入口顯示名稱，按「新增入口」。實體路徑不送到瀏覽器；目錄必須已存在，不能與 state 或已註冊入口重疊。候選來源若被替換應由主機管理者重新確認，移除候選後重新登記。

可調整入口顯示名稱、停用／恢復及 Linux 寫入 opt-in。外部 mount 預設仍唯讀，改入口旗標不會改 OS mount 權限。入口及 grant 必須同時允許寫入；Windows 是唯讀開發環境。

授權選帳號、入口與相對目錄（留空為入口根目錄），再選下載／寫入。相同 key 更新原 grant，多份 grant 採正向聯集；取消下載／寫入即只保留瀏覽。撤回後下一次請求／背景檢查使用新規則，既有已送出的 bytes 不能收回。進行中的核心 I/O 不會被管理操作搶占。

密碼更新撤銷登入；工作和分享仍按目前 owner 的啟用與檔案授權判斷。要永久停止公開連結需到「分享管理」撤銷，停用再恢復帳號／入口可能使有效分享重新可讀。完整政策及上限見[管理決策](../decisions/P6-settings.md)。
