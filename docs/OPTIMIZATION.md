# FileHub 優化驗證紀錄

## 列表效能量測

使用專用測試空間；工具只清理自己建立的 `filehub-benchmark-*` 暫存資料夾，不修改既有檔案。
`--parent` 必須是已存在且可寫入的測試目錄。每個規模建立 10% 資料夾、90% 小檔案，預設執行五次。

```sh
python -m scripts.benchmark_listing --parent /tmp --label linux-local > listing-local.json
python -m scripts.benchmark_listing --parent /nfs/test-scratch --label linux-nfs > listing-nfs.json
```

同一台主機、同一個磁碟或掛載、相同 Python 環境分別執行修改前後版本，再比較中位數。
也可加上 `--baseline-ref <可信任的 Git commit>`，在同一批檔案交錯執行目前版本與基準版本；這個選項會載入並執行該版本的 FileService 原始碼，僅限可信任的版本。
時間容易受防毒、磁碟快取與其他程序影響，退步超過 10% 時應使用交錯比較調查，不能只挑最快的一次。

Windows 單檔列表追蹤：Path.stat 呼叫由 10 次降為 8 次。此數字含路徑安全驗證，不代表系統呼叫總數。
量測涵蓋 FileService 的完整列表、路徑驗證與序列化回應大小；不含 HTTP、帳號資料庫授權或瀏覽器渲染時間。
秒數只量列表建構；回應大小另外計算。輸出包含每次秒數、中位數、UTF-8 JSON 位元組數、外部程序啟動次數。
Windows 原本即有原生建立時間，因此本機結果不能用來推估 Linux 移除逐檔 stat 程序的收益。

## 相容性

建立時間只使用檔案系統原生提供的值；不提供時回傳 `null`，不以修改時間冒充。
不變更目錄列表格式、排序、授權、資料庫結構或單程序部署方式。
Linux Docker 與 NFS 實際環境驗證須獨立記錄，不能由 Windows 測試推論。

## 就緒與診斷介面

`GET /api/ready` 不需登入。正常回傳 HTTP 200、`{"status":"ok"}`；SQLite 查詢失敗、背景工作者停止或不存活時回傳 HTTP 503、`{"status":"unavailable"}`。
`GET /api/health` 保持原狀。兩者都不是外部目錄健康承諾；就緒檢查不探測檔案根目錄或共享目錄。
API 回應提供伺服器產生的 `X-Request-ID`，不信任用戶提供的識別碼；紀錄不包含完整 URL 或請求內容。
目錄檢查十秒逾時只結束瀏覽器等待，不能保證中斷伺服器或核心中的 NFS 操作；人工重試前應先確認主機儲存狀態。
