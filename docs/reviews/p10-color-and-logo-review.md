## 1. 判斷與證據

建議保留藍色操作，將其他顏色的用途分得更清楚：**墨藍負責操作，中性灰承載資訊，暖金辨認資料夾**。Logo 由圓框 F 改為資料夾輪廓與負形 F。這是基於產品畫面與原碼的視覺判斷，沒有訪談或 A/B 實驗，不宣稱使用效率已改善。

檢視了 P9.8 的桌面列表、個人設定、登入與手機列表原圖，另核對現行 theme、CSS 及三處品牌 host。8088 分頁目前顯示登入到期；實際登入頁仍量得主按鈕 `rgb(36,94,168)`／白字、輸入邊界 `rgb(129,144,162)`，版本 0.40.14。沒有取得密碼、登入私有工作區或擷取私人檔案畫面。

## 3. SVG 交付與使用

- [彩色 SVG](../design/P10/assets/filehub-symbol.svg)：墨藍資料夾、暖金頁籤、透明負形 F；適用白／淺背景。
- [單色 SVG](../design/P10/assets/filehub-symbol-mono.svg)：相同外輪廓與 F，深灰單色。
- [反白 SVG](../design/P10/assets/filehub-symbol-reverse.svg)：深色背景使用；不代表產品新增深色主題。

均為本次以 path 手繪的原生 SVG，`viewBox="4 6 40 40"`；沒有位圖、字型依賴、script、外部資源或 filter。16／24／32／48／128px 已在 Chromium 實際解碼並看圖；16px 保留基本 F 與資料夾輪廓，不宣稱經過所有平台 favicon hinting。

字標繼續用 HTML 的 FileHub 與既定字型；不要將文字轉成一張底圖。品牌連結已有 `aria-label` 時，內部 `<img alt="">` 或裝飾性 inline SVG 不重複朗讀；獨立圖片需要 FileHub 替代文字。外部 SVG `<img>` 不繼承宿主 currentColor，所以提供明確的三種 fill。三個檔案含同名 title ID，若未來改 inline，必須處理多實例 ID；推薦共用元件先用外部 asset。
