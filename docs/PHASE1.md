# 第一階段：檔案日常操作

以 React + Ant Design、FastAPI 與既有 Docker 部署為基礎，加入類似桌面檔案管理器的基本操作。

## 已實作

- 多檔選擇／拖放上傳；單檔 512 MB、每批最多 100 個、同時傳輸 2 個。
- 傳輸面板顯示進度、完成／失敗狀態，支援取消與重試。加入佇列時固定目的資料夾，切換目錄不改變目的地。
- 單檔串流下載，保留中文及特殊檔名；下載前檢查登入與檔案存在。
- 檔案／資料夾重新命名；Windows 與支援的 Linux 檔案系統使用原子、不覆寫的操作。
- 單擊選取、雙擊／Enter 開啟、核取方塊與 Ctrl／Command 多選、右鍵及更多操作選單。
- 保留原本登入、密碼修改、目錄樹、搜尋、預覽與建立資料夾。

## 操作規則

- 同名上傳／重新命名回報衝突，不會覆寫原項目。
- 上傳先寫入目的目錄的隱藏暫存檔，完整傳輸後才發布；一般中斷與失敗會清理暫存。
- Docker Desktop 的 Windows 掛載若不支援 `RENAME_NOREPLACE`，改用程序內共用鎖保護存在檢查及重新命名。此相容模式限單一 worker／容器，外部程式不可同時更動相同目的路徑；不要對同一根目錄啟動多個寫入服務。
- 取消時若伺服器已完成儲存，檔案可能已存在；介面會提醒重新整理確認。重試仍遵守不覆寫規則。
- 關閉／重新整理頁面會停止尚未完成的傳輸；不提供斷點續傳。傳輸記錄只保留於目前頁面。
- 程序被強制終止或斷電可能留下 `.files-app-upload-` 暫存檔；它們不可由檔案 API 存取，維護者可在停止服務後檢查並清理。
- 暫不包含資料夾上傳、批次移動／複製、垃圾桶、分享連結、獨立使用者目錄。

## 檢查與修正

- 修正選取工具列出現造成清單位移、雙擊誤開另一個項目的問題：工具列固定占位。
- 統一取消／重試按鈕的無障礙名稱，避免中文自動間距影響操作定位。
- 禁止使用上傳暫存保留名稱建立資料夾，避免建立後無法存取。
- 瀏覽器測試命令先建置最新前端，避免驗證到過期產物。
- 修正 Docker Desktop Windows 掛載拒絕 `RENAME_NOREPLACE`，導致上傳／重新命名失敗的問題，加入掛載相容處理。
- 後端 46 項測試通過，包含權限、路徑、特殊名稱、同名競態、掛載相容處理、傳輸大小、中斷清理、重新命名及下載位元組比對。
- Chromium 8 項端到端測試通過：包含既有流程、手機版、連點、拖放、重試、取消與下載。取消案例在瀏覽器攔截請求，後端另測中斷的串流清理。
- Docker 測試由 `backend.tests.docker_smoke` 建立獨立專案與暫存資料，驗證非 root、上傳、同名保護、重新命名、下載、重建後檔案及登入持續有效。
